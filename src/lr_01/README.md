*[СКВ]: Система контроля версий
- `─` обозначает элемент (каталог или файл)
- `<` обозначает элемент, игнорируемый СКВ по умолчанию;
- `*` обозначает элемент, игнорируемый СКВ (указан в файле *.gitignore*);
- `>` обозначает элемент, игнорируемый СКВ локально (на уровне проекта конкретного пользователя — для корректного использования и отображения должен быть указан в файле *.git/info/exclude*)
- `>>` обозначает элемент, игнорируемый СКВ глобально (на уровне системы конкретного пользователяa — для корректного использования и отображения должен быть указана в файле *~/.gitignore_global*)

## 3. Решение заданий

### 3.1 Задание 1

#### 3.1.1 Анализ исходных данных
Условие:
- в поля формы вводятся натуральные числа, представляющие длины сторон треугольника;
- после нажатия кнопки "Проверить" производится валидация входящих данных и определение вида треугольника по сторонам;
- на основании произведенного расчета выводится сообщение о том, какой это треугольник: равнобедренный, равносторонний или разносторонний;
- в случае ввода невалидных данных выводится сообщение об ошибке.

Исходные данные:
- $a, b, c \in \Bbb N$ — длины сторон треугольника.

Требуемый результат:
- $k \in \{ равносторонний, равнобедренный, разносторонний \}$ — вид треугольника по сторонам.

#### 3.1.2 Математическая формализация

В общем виде функция определения вида треугольника по сторонам может быть представлена следующим образом:

$$
f(a, b, c) =
\begin{cases}
k = равносторонний,  & a = b = c \\
k = равнобедренный, & a = b \lor b = c \lor a = c \\
k = разносторонний
\end{cases}
$$

#### 3.1.3 Алгоритмизация и программирование
Для реализации поставленной задачи разработано веб-приложение с использованием языка разметки HTML5+, стилизации при помощи CSS3+ и языка программирования ECMAScript (JS LS). Программа запускается в среде Node.js с помощью сценариев пакетного менеджера NPM. Весь программный код содержится в текущем каталоге, точкой входа в приложение является файла *index.js*. Основной программный код содержится в каталоге *scripts*, файлы стилей — в папке *styles*.

Управление приложением осуществляется в среде Node.js при помощи сценариев пакетногого менеджера NPM в консольном режиме. Все команды выполняются в текущем каталоге (root directory).

Команда развертывания приложения:
```sh
$ npm install # Полный вариант команды
$ npm i       # Быстрый вариант команды
```

В результате выполнения данной команды будет выполнена установка всех необходимых зависимостей, настройка и подготовка приложения к запуску.

Команда запуска приложения:
```sh
$ npm run serve # Полный вариант команды
$ npm start     # Быстрый вариант команды
```

В результате выполнения команды проект будет запущен в новой вкладке браузера.

Веб-интерфейс приложения разработан с использованием двух основных техник валидации:

- мгновенная неблокирующая валидация на уровня ввода данных в поля форм с использованием встроенных средств ограничительной валидации (HTML5 Constraint Validation), отображающая состояние валидации фоновым цветом полей формы (зелёным обозначаются валидные данные, красным — невалидные);

- валидация на уровне бизнес-логики приложения конструктором класса данных, осуществляемая после отправки данных формы и отображающая валидационные сообщения в блоке вывода результата формы.

#### 3.1.4 Отладка и тестирование
Для отладки программы использовалась среда разработки Visual Studio Code и браузер Google Chrome.

Для тестирования используются программный комплекс Jest, позволяющий осуществлять создание модульных (unit) тестов, запуск тестовых наборов и автоматическое формирование отчётной документации, а также Selenium (в формате веб-драйвера под управление Jest), позволяющий производить сквозное (E2E) тестирование. В основу тестовых сценариев положено два базовых подхода тест-дизайна:

- метод эквивалентных разбиений;
- техника анализа граничных значений.

Первый основан на математическом понятии классификации дискретных структур, опирающемся на отношении эквивалентности (бинарное отношение на множестве, все элементы которого одновременно находятся в отношениях рефлексивности, симметричности и транзитивности). <dfn title="класс эквивалентности">Классом эквивалентности</dfn> $[a] \subset X$ элемента $a \in X$  называется подмножество элементов, эквивалентных $a$; т.е.

$$
[a] = \{ x \in X \mid x \sim a \}
$$

С точки зрения программирования, <dfn title="класс эквивалентности">классы эквивалентности</dfn> — это группы входных данных, которые обрабатываются программой одинаково. Суть метода в том, чтобы вместо тестирования всех возможных значений проверить по одному представителю из каждого класса исходя из математического определения отношения эквивалентности. Традиционно рекомендуется брать значение из середины класса, т.к. при этом ничто не влияет на логику обработки. Это дает возможность сократить количество тест-кейсов, сохраняя эффективность проверки.

Второй подход является логическим дополнением техники эквивалентных классов, при которой помимо проверки значений из середины класса проверяются значения на границах. <dfn title="граничное значение">Граничные значения</dfn> – значения диапазона входных данных, при которых меняется поведение приложения. Это соседние значения диапазона, но относящиеся к разным эквивалентным классам. И хотя сами граничные значения являются элементами/представителями своих классов, они должны быть протестированы в дополнение к проверке значения из середины класса. Необходимость заложена из предпосылок потенциальной уязвимости границ диапазонов.

Сценарии тестирования в виде тестовых наборов расположены в каталоге *test*.

Команды запуска разных сценариев тестирования:
```sh
$ npm run test:unit # Запуск набора модульных тестов
$ npm run test:e2e  # Запуск набора сквозных тестов
$ npm test          # Запуск полного набора тестов
```

Данные команды выполняют тестирование по соответствующим наборам с выводом информации в консольном виде, по завершении которых автоматически формируют отчёты о результатах тестирования и аналитику по тестовому покрытию в форматах xml и html, размещаемые в каталогах *test/reports* и *test/coverage* соответственно. Отчеты и аналитика также доступны по соответствующим ссылкам на главной странце приложения.
